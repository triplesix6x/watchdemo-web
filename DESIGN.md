# WatchDemo: повторный выбор направления

Статус: пользователь выбрал A «Фокус» как наиболее близкое направление. Для интерактивности пользователь выбрал заметный локальный подъём рельефа под курсором и волну при нажатии. Следующий этап: создать изолированный интерактивный прототип A с этим откликом. Это ещё не утверждённая спецификация полного редизайна сайта и desktop.

## Brief

Сайт Windows-приложения для библиотеки демо CS2, моментов, наборов, 2D и просмотра в CS2. Первый экран представляет весь продукт. Новая композиция целиком, чистая продуктовая выразительность. Сайт и desktop рассматриваются вместе, структура desktop сохраняется. Onest сохраняется. Все реальные матчи, игроки, события и исходные демонстрационные данные сохраняются. Исходные рабочие файлы не изменяются на этапе сравнения.

Topography должна быть заметным интерактивным фоном первого экрана. В этих статических исследованиях SVG показывает только масштаб и контраст линий, не заменяет ReactBits. Реальная интерактивность будет проверена в следующем прототипе выбранного направления. Видео настоящего запуска в CS2 пользователь снимет по сценарию; ни одного вымышленного игрового кадра нет. Видео и исходная 2D-история остаются отдельными эпизодами. Телефон получает крупный 2D-блок, не маленькую постоянную полосу.

## Stack and boundary

Существующий продукт: React/Vite, Svelte/Tauri, GSAP. Для сравнения: изолированные HTML/CSS-макеты в docs/design-review, без новых зависимостей и изменения роутов. Это самый короткий путь сравнить статическую композицию, не вмешиваясь в продукт. Просмотр через локальный HTTP-сервер. Никакого деплоя или запуска native/Steam.

## Общая система

Шесть основных цветов: Ground #02070A, Surface #0B1821, Text #EDF5FA, Muted #A2B3BF, Blue #0297DE, Orange #FC734D. Разделители: прозрачность Text, не дополнительный акцент. Синий основной для действий, оранжевый заметный второй цвет в полях/указателях смыслового фокуса. Оранжевый не заменяет цвета команд и статусов. На ярком синем тёмная подпись, не белая. Desktop в макетах: цветовое исследование на исходном скриншоте, не работающая сборка. Реальные подписи и положение элементов не меняются.

Onest из уже установленных локальных fontsource-файлов. Display 64–88 px desktop / 40–48 px phone, weight 600, tracking -0.045em, leading 1.02. Body 17/1.55, UI 13–14/1.4. Без нового шрифта, искусственного сжатия или uppercase-этикеток. Основной ритм 8 px; поля desktop 64–80, phone 24. Продуктовые изображения не рисуются div-элементами. Радиус внешней рамки 16 px, кнопок 8 px. Тени только для отделения настоящих изображений. Планируемый motion verb: фокусировать / выравнивать / раскрывать для A/B/C; критически затухающие реакции, один GSAP clock, reduced-motion без GL и скролл-хореографии. В текущих статических макетах анимации намеренно нет.

## Три направления

### A. Фокус

Territory: процесс. Anchor: из библиотеки реального матча пользователь выбирает нужные моменты и наборы. Смысл: один матч собирается в удобное место разбора. Эмоция: ясность и контроль. Signature будущего прототипа: выбор инструмента мягко фокусирует настоящий фрагмент интерфейса, без изменения данных. Screenshot: крупный левый заголовок и правый интерфейс, оранжевая смысловая планка под изображением. Граница: никакой трансформации радара в псевдо-CS2.

```
logo                         navigation
[широкий заголовок]  [настоящий интерфейс]
[описание, CTA]      [оранжевая полоса инструментов]
          видимый контурный рельеф
```

Выравнивание: две сильные вертикальные оси, копирайт слева, изображение справа без perspective. На телефоне текст, CTA, увеличенный фрагмент настоящей рабочей области в отдельном горизонтально доступном регионе. Кадрирование не меняет данные, скрытые края доступны прокруткой; область фокусируется с клавиатуры. Desktop-направление: спокойные тёмные панели, основное синее действие, оранжевый только как смысловой акцент сайта вокруг инструмента. Не добавлять новые панели в приложение.

### B. Пространство разбора

Territory: материал профессии. Anchor: библиотека и журнал разбора WatchDemo объединяют разные инструменты для одной демки. Смысл: настоящий интерфейс становится общей рабочей плоскостью, инструменты не конкурируют за отдельные карточки. Эмоция: собранность и простор. Signature будущего прототипа: широкий интерфейс выравнивается в общей плоскости, затем отдельно открывает видео и 2D. Screenshot: крупный двухстрочный заголовок над широким настоящим приложением; оранжевая боковая подпись привязывает инструменты к рабочей области.

```
logo                         navigation
           Разбор матча.
           Всё в одном месте.
       lead + download / walkthrough
[оранжевый указатель] [широкий настоящий интерфейс]
```

Выравнивание: заголовок по центру общей рабочей области; изображение по ширине, не поверх градиентного шара. Topography видна слева и справа и в верхнем поле, без свечения. На телефоне сохраняется центрированная типографика, оранжевая полоса инструментов переносится над крупным фрагментом рабочей области. Это отличает мобильное B от левого выравнивания A. Desktop: те же привычные панели, спокойная глубина, синий активный контроль. Рекомендуемое направление по смыслу всего продукта, но выбор за пользователем.

### C. Слои матча

Territory: формальная система. Anchor: одна демка имеет библиотечное, событийное и пространственное представление. Смысл: несколько способов смотреть на одну и ту же информацию. Эмоция: точность без тяжести. Signature будущего прототипа: один вертикальный направляющий элемент последовательно раскрывает реальные представления матча; это не карточный карусельный шаблон. Screenshot: заголовок сверху слева, пояснение справа, широкая продуктовая плоскость под ними, оранжевый вертикальный инструментальный индекс.

```
logo                         navigation
[заголовок, 2 строки]    [описание + CTA]
[оранжевый индекс] [настоящий интерфейс на всю ширину]
       спокойный рельеф в свободном поле
```

Выравнивание: открытая 12-колоночная сетка с отдельной узкой колонкой инструментария. На телефоне индекс становится строкой смысловых обозначений над большим фрагментом интерфейса. Desktop: исходная структура неизменна, контуры поверхностей чуть определённее; не добавлять сам индекс в приложение.

## Сравнение концептов

Внутренние проектные оценки 1–5, не Awwwards-аудит готового сайта. Portability: меньше лучше.

| Направление | Originality | Fit | Feasibility | Portability |
|---|---:|---:|---:|---:|
| A: процесс фокусировки | 3 | 5 | 5 | 3 |
| B: общая рабочая плоскость | 4 | 5 | 5 | 2 |
| C: несколько представлений одной демки | 4 | 4 | 4 | 2 |

Первоначальная рекомендация дизайнера была B. После просмотра пользователь выбрал A «Фокус»: его композиция ближе желаемому результату. A становится единственной основой следующего интерактивного прототипа. B и C остаются историческими альтернативами, а не направлениями дальнейшей реализации.

## Genericness test и ограничения

Убраны псевдостатистика, три равные карточки, игровая иллюстрация, диагональные fake-window стопки и новый синтетический матч. Различия выражаются композицией настоящего интерфейса и иерархией текста, а не разными оттенками одного шаблона. Центрированное B сознательно использует продуктовую плоскость вместо шара/градиента; отдельная оранжевая смысловая область нужна для считываемой трёхцветной системы. Контуры везде достаточно различимы, но за текстом ослабляются.

## Структура следующих эпизодов (не реализуется сейчас)

A: asymmetric hero → отдельный широкий видеоэпизод → sticky 2D narrative → наборы/заметки в неповторяющейся сетке → тарифы/CTA.
B: широкая рабочая плоскость → асимметричная запись запуска → крупный локальный 2D-эпизод → реальные представления библиотеки/наборов → тарифы/CTA.
C: асимметричный заголовок + слои → видео отдельной плоскостью → крупный 2D → обзор функций по общей оси → тарифы/CTA.

Полные страницы, 404, production SEO/производительность, живой GL и native Windows поведение здесь не проверяются и не объявляются готовыми. Следующий этап только после визуального выбора. Desktop-цветовые эскизы не доказывают достаточный контраст всех состояний; это предмет реализации и проверки.
