Ниже сохранён ранний журнал восстановления и ресурсных ограничений; промежуточный checkpoint находится в `docs/LEGAL-CHECKPOINT.md`.

## Ограничение ресурсов

Для локальных проверок используется `docs/scripts/run_limited_check.sh command [arguments...]`:

- общий неблокирующий lock на пользователя, чтобы две проверки не запускались одновременно;
- перед запуском должно оставаться минимум 4 GiB доступной RAM;
- отдельный systemd user scope: `MemoryMax=768M`, `MemorySwapMax=0`, `CPUQuota=75%`, `TasksMax=128`; ещё максимум 256 MiB / 25% CPU зарезервированы для единственной disposable БД, только если она нужна текущему тесту. Общий бюджет проверки вместе с БД — не больше 1 GiB / одного CPU;
- если scope недоступен, не происходит запуска без ограничений;
- Docker/Podman напрямую через runner запрещены: контейнеры не наследуют ограничения CLI-процесса. Если потребуется отдельная тестовая БД, лимиты контейнера задаются явно и чужие контейнеры не используются.

Проверено после перезапуска: первоначально реальные значения cgroup были `memory.max=1073741824`, `memory.swap.max=0`, `cpu.max=100000 100000`, `pids.max=128` (установка окружения и первые проверки). После резервирования бюджета БД runner ужесточён; повторная проверка показала `memory.max=805306368`, `memory.swap.max=0`, `cpu.max=75000 100000`, `pids.max=128`. Проверка синтаксиса `bash -n` прошла.
