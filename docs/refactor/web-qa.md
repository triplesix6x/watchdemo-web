## Selection and bounded execution

D25 uses a **layered** plan: 169 case IDs / 245 screenshots, not a Cartesian state × width × motion × repeat × time expansion. Principal layouts cover all five agreed widths and RU/EN; state/interaction boundaries cover 390/1280 and RU/EN. Existing RU-only controls are the explicit exception. Normal-motion principal layouts at 390/1280 get three independent noise probes; other cases get one capture. Reduced motion is a separate home/controls representative layer. There are no automatic three temporal frames: `home-scroll` is an explicit additional animated boundary. Every exported case carries its layer, rationale, capture count and exact ID before capture. See the contract matrix for deliberately omitted cross-products.

`diagnostic` requires one to three exact case keys and a budget sufficient for the selected layered screenshot count. Every screenshot also writes one DOM JSON record; `manifest.json`, the Vite cache and the complete isolated production `site` build are additional artifacts. `--budget` is a **screenshot-count ceiling**, not a byte limit. Parent disk/time/job limits remain necessary, particularly for full-page home images. `slice` also requires explicit keys and budget and is nonaccepting. `full` refuses any case filter and requires the entire implemented representative matrix; it explicitly reports missing, unexpected and duplicated cases. It does **not** mean all source modules are covered. No mode automatically grants acceptance, including a byte-exact full comparison.

Do not start with full mode. First integrate/review/test W0, then the offline tests below, then a single small diagnostic case. Inspect DOM assertions, errors, metadata and images before expanding. A timeout or unsupported selector is an unexecuted/failed gate, not permission to skip it or fix production behavior. Full representative execution is an explicit later opt-in, never a forced prerequisite for diagnostics. Slice aggregation into full acceptance is not implemented: separate slices remain incomplete; do not claim their union passed without a separately reviewed completeness gate.

## Determinism, metadata and D21

Each capture runs in an independent fresh context, resetting mock state and starting from QA time `2026-05-20T12:00:00.000Z`, timezone UTC, DPR 1, explicit viewport/locale/motion. Playwright's virtual clock is paused before navigation and advanced only by the existing scenario steps; normal animations are **not** disabled. Initial font readiness is bounded at 15 seconds. After DOM/fixture assertions, fonts and image decoding have a 15-second bound, followed by a finite 15-second asset-status/HTTP-completion check using host-side polling, not Vite `networkidle` or extra virtual-time advancement. All document images must decode and be complete; a lazy/broken image that cannot settle fails rather than being silently excluded. Existing admin-loading mock promises remain pending at virtual 1200ms; modal/focus and async-stale assertions are unchanged. HTTP status errors and failed requests join the fail-closed ledger, with per-capture in-flight diagnostics retained before context teardown. Startup networking/font work and animation phase can still cause noise and must be characterized from unchanged repeats, not assumed deterministic. No custom global WAAPI overrides are installed; animation determinism remains an unresolved separate gate.

The QA init script seeds `Math.random` with LCG seed `240621` and derives UUIDs from it. This controls QA-only incidental identity/random graphics initialization, not production parameters. The existing mock fixture generator retains its own original seed `20261023`; its relative dates use the QA clock. No mock response or legal text is invented. Fixtures are identified by hashes of their existing source in the manifest. The deferred-hook fixture is the sole additional data source and has explicit `old`/`new` values.

Manifest records source HEAD/status/per-file hashes (dotenv files excluded without reading), Node/OS identity, installed dependency package-manifest hashes/versions and lockfile hash, Edge executable hash/version, GPU vendor/renderer/unmasked identity, viewport/DPR/language/fonts, seed/time, scenario contract/assertions, screenshot/DOM hashes and request/page/console error ledger. Dependency hashes identify manifests and the lockfile, **not a forensic hash of every installed package byte**. Parent should retain its installed-dependency provenance. No inherited environment values or source secrets are serialized.

D21 is intentionally fail-closed: each designated noise probe's three PNG and DOM hashes must agree exactly. Single-capture state/dimension cases explicitly record `noiseMeasured:false`; their own noise is not claimed measured and they remain subject to parent review of representative probe applicability. Any repeated-capture difference is `noise-unresolved`; no arbitrary percentage, masks, animation suppression or invented tolerance is applied. Stable actual differences are `regression-review-required`; byte-identical results still require golden/DOM review. Comparisons reject unresolved baseline noise. The infrastructure does not implement a calibrated pixel noise model or classify geometry/color/text/graphics changes automatically; DOM records include text, key element geometry/computed styles and canvas dimensions to support manual review. The parent must inspect all stable differences and derive any future noise treatment from repeated unchanged captures before accepting it.

D26 fixes canonical visual captures to QA-only `--disable-gpu`; browser arguments and the software-golden policy are recorded. This changes no production graphics parameter. Real-GPU native smoke and performance checks remain separate requirements. WebGL capability metadata uses a detached canvas and a temporary WebGL context inside the same capture page; the context is explicitly lost after reading metadata. It does not create a separate Playwright browser context. This is neither a whole-home trace/performance oracle nor physical iOS Safari/Android Chrome evidence. Fixed frame moments, full graphics parity and native-device performance remain open gates.
