## Подключение провайдеров: серверная конфигурация

Соцвход по умолчанию отключён. На локальных снимках disabled-кнопки и сообщение «Сервис не настроен» ожидаемы. Наличие кнопки не означает работающий вход у провайдера.

Значения задаются только в приватном серверном окружении:

```dotenv
SOCIAL__API_ORIGIN=https://watchdemo.pro
SOCIAL__STEAM_ENABLED=true
SOCIAL__FACEIT_CLIENT_ID=<private OAuth2 client id>
SOCIAL__FACEIT_CLIENT_SECRET=<private OAuth2 client secret>
SOCIAL__FACEIT_AUTHORIZE_URL=https://accounts.faceit.com
SOCIAL__FACEIT_TOKEN_URL=https://api.faceit.com/auth/v1/oauth/token
SOCIAL__FACEIT_USERINFO_URL=https://api.faceit.com/auth/v1/resources/userinfo
```

Здесь нет настоящих секретов. Указанные FACEIT endpoints сверены агентом с официальным OAuth-описанием/discovery, но реальный ответ настроенного клиента пока не получен; до включения сверить настройки конкретного OAuth2 Client. Не использовать API key вместо Client Secret. Авторизация использует PKCE S256, `openid profile`, серверный token exchange с HTTP Basic и стабильный subject.

Callback FACEIT: `https://watchdemo.pro/api/v1/auth/social/faceit/callback`; Steam: `https://watchdemo.pro/api/v1/auth/social/steam/callback`. Origin frontend должен соответствовать `APP__FRONTEND_URL`, поскольку социальные мутации проверяют Origin. Локальный callback регистрируется отдельно. Нельзя подменять origin production для внутреннего стенда или добавлять фальшивые credentials ради зелёной кнопки.

Текущий локальный Compose имеет внутреннюю сеть без egress. Он пригоден для приложения, UI и локальных сценариев, но не для фактического обращения к Steam/FACEIT. Реальный provider flow требует доступного HTTPS origin, сетевого доступа и контролируемого тестового аккаунта. Передача секретов в чат, frontend bundle или Git запрещена.

### Передача реальной проверки владельцу — 13 ноября

Владелец создал FACEIT OAuth2 Client, получил секреты и решил сам проверить вход после выката. Поэтому приватный файл и отдельный тестовый origin у него не запрашиваются. Реальная авторизация у провайдеров остаётся **непроверенной**; это решение не является разрешением агенту выполнять deployment.

Production `docker-compose.yml` передаёт серверу настройки через `web.env_file: .env`. Владелец размещает приведённые выше ключи в приватном серверном `.env`, а не в `VITE_*` или исходниках. После изменения окружения контейнер web должен быть пересоздан штатной процедурой выката: простой restart не перечитывает `env_file`. До включения требуется применить миграции `0007_social_auth` и `0008_maintenance_notice` в предусмотренном проектом порядке. Steam использует OpenID и отдельного Steam Client Secret в этой реализации не требует.

Приёмка после выката:

1. На входе и регистрации оба настроенных провайдера доступны; Steam имеет логотип слева и тёмно-синее оформление, FACEIT — логотип слева и оранжевое оформление. Тексты RU/EN сохранены.
2. Новый вход через каждый провайдер приводит к обязательному выбору уникального имени, затем в кабинет; email и пароль не требуются. Повторный вход возвращает в тот же аккаунт.
3. В существующем кабинете можно явно привязать свободный профиль провайдера. Занятый профиль отклоняется без переноса и объединения аккаунтов; уже привязанный отображается недоступным для повторной привязки.
4. Отмена у провайдера и повтор callback не создают аккаунт и не ломают обычный вход. При ошибке остаётся доступен повторный вход через страницу авторизации.

Новые брендовые кнопки используют общий компонент для login/link/reauth, локальные SVG без внешних запросов и новые focus/hover/disabled стили. `check:social-provider-brand-component-source-20261113` — PASS: TSX/CSS syntax и неизменность подписей/атрибутов поведения по сравнению с HEAD.
