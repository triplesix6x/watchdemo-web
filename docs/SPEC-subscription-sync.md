## 3. Periods and tier transitions

Use server UTC exclusively. Free period is [first day 00:00 UTC, next month's first day). Paid periods use calendar-month arithmetic from the ORIGINAL continuous-paid-activation timestamp, preserving day/time and clamping short months independently (Jan31 -> Feb28/29 -> Mar31), never fixed 30 days or iterative clamped anchors. Expiry boundary is `now >= expires_at`.

Same active paid regrant, extension/date changes and Plus<->Pro switches preserve the paid-cycle anchor and usage. Pro is unlimited but accounted. Returning to Plus counts all operations in its current paid period, including Pro. Expiry/revocation followed by a new activation starts a new paid cycle. Free downgrade counts all successful operations in the current UTC calendar month, regardless of tier when performed. Initial paid activation does not include pre-activation Free usage. UI renders server reset timestamps in local timezone.

Existing import/set historical consumption is NOT reconstructed or backfilled: accounting starts with new protocol operations. Existing groups ARE reconciled as inventory, even above cap. Existing groups/sets/demos stay intact.

## 4. Import selection UX

Preflight locally extracts/checks candidates, excludes catalog duplicates, and assigns stable opaque candidate IDs. Keep local paths/names out of remote requests. If valid NEW candidates exceed server remaining quota, show selection dialog BEFORE import: checkboxes, `selected N / available M`, Cancel and Add. Do not automatically import an arbitrary prefix. Zero remaining shows the explanation/reset and cannot add. Unlimited tier needs no quota-selection interruption.

On confirmation atomically reserve the whole selected batch. Another device can consume capacity meanwhile: if insufficient, import NOTHING and return updated quota to the SAME selection dialog, preserving selections for user correction. Never silently reduce selected batch. Failures processing an authorized item do not require rolling back other successful items; show explicit added/duplicate/failed/quota/network outcomes. Lost responses retry original IDs, not new ones.

## 5. Groups, libraries and support

Persist an opaque library UUID per account-local database. Server stores opaque group UUIDs per account/library; count is SUM of libraries, not maximum. Reconcile on every online activation before permitting new group creation; server missing local groups must be restored even above quota. Reconciliation is additive, never an authoritative replacement that can silently decrease server inventory. Explicit idempotent delete operations (or support) reduce it. Offline deletion queues a tombstone; account slot frees only after server confirmation. Validate account/library ownership on every operation, never accept another user's identifiers.

Support decision: `support` and above can reset group inventory for the WHOLE ACCOUNT, not selected library. Follow existing strict target rules: no self, no higher role, no equal except admin. Require nonblank reason, audit actor/target/reason/time/counts. Reset only groups, NEVER imports or monthly set usage or subscription. Increment a group-account generation/revision so stale requests do not quietly restore old grants. Every returned library must reconcile its ACTUAL local groups after reset, which restores their count (possibly above cap) before any new creation. Queued deletions process idempotently against their exact old identities. No public self-reset or device-management page.

Generation protocol refinement (coordinator accepted during implementation): stale supplied generation on reconcile returns `LIBRARY_RECONCILIATION_REQUIRED` with current snapshot. Absent generation is accepted only for initial generation 0. After reset, or for a new installation at nonzero generation, fetch `/access` then reconcile actual local inventory with the current generation. Persist each library's reconciled generation; group reservation requires it to equal account generation. Support reset invalidates outstanding group reservations, preventing stale group commits from bypassing reconciliation.

Own-set loss does not need support reset: allowance renews next month. User explicitly rejected resetting import and set usage.

Security boundary: honest app reconciliation prevents ordinary reinstall/old-library reuse. Server cannot inspect a modified local database/binary, prove true disk inventory, or stop a user creating another account. State this honestly; do not claim remote enforcement of arbitrary offline files.

## 6. Crash-safe accounting and concurrency

Prefer one persistent server operation ledger and one durable local pending-operation journal; reject independent check-then-increment and counting surviving catalog rows. Compare alternatives: local-only metering is simpler but fails reinstall/multi-device requirements; decrement-first with refunds creates crash/accounting gaps; choose reserve/stage/commit/publish for server authority and recoverability.

Serialize quota-changing transactions per account (PostgreSQL row lock, not a Python mutex). Check committed usage + live reservations atomically. Batch reservation is all-or-none. An operation ID is opaque UUID scoped to authenticated account and permanently bound to kind/library; replay returns the same state; incompatible ID reuse is conflict. Kinds: `demo_import`, `custom_sets`, `demo_groups`. Pro uses same ledger without denial.

Reservation lifetime: 15 minutes server time; expired uncommitted reservations can be reclaimed on subsequent reads/writes, never convert themselves into charges. Commit/cancel transitions must be serialized/idempotent; committed cannot be cancelled/refunded. Repeated commit returns original outcome, even after period change. Invalid/expired/cancelled reservation does not grant publication rights. The IMMUTABLE metering timestamp is the server's first reservation `created_at` (authorization time), not commit time. Use it for both live reservations and committed usage in every calendar/paid-period query. Commit timestamp is audit only. Reserve-before/commit-after rollover stays in the old period; initial paid activation excludes pre-anchor reservations; Free downgrade includes all tiers' reservations timestamped inside its current calendar month. Store this assignment once; new operations use current server entitlement. Add a shared boundary fixture.

Before commit, durable local staged data + operation ID must exist but not be visible as an imported catalog row/new set/group to other commands/UI. On confirmed server commit publish locally exactly once. On response loss ask status/retry with the SAME IDs. On crash recover staged operation before accepting new work; committed stage publishes, safely cancelled/expired stage is removed without consuming quota, uncertain network stage stays pending and is not imported again. Never cancel when publication/commit outcome is unknown. A committed operation with durable staged local success remains charged if user later destroys the database. Journal and object publication must use SQLite transactions where applicable.

Accepted independent-review requirement: auth activation/session epoch must protect every async auth transition, keyring write, lease/profile cache update, invalidation and library activation/deactivation, not just quota publication. Advance epoch on logout/session replacement and validate it atomically when applying async results; checking only account UUID misses A-to-B-to-A and same-account relogin races. A stale refresh rejection must never log out the replacement session.

Library identity, migration marker, staging, tombstones and mutation journal are per-user SQLite, not global shared mutable state. Check auth account continuity across network awaits; no result may be applied to a newly switched user's library. Avoid holding unrelated SQLite transactions over HTTP. Local concurrent calls must not create duplicate groups/sets or publish one operation twice.

## 7. Shared HTTP contract (protocol v1)

Prefix `/api/v1/app`. Existing public `GET /tiers` remains descriptive and adds explicit scope/period semantics (monthly own sets, account quantity groups). Missing new fields must not silently grant permission in desktop. Strict DTOs, version check; UI gets canonical snapshot via IPC, never talks to authenticated quota HTTP directly.

Authenticated endpoints:
- `GET /access?library_id=<uuid>` -> `AccessSnapshot`.
- `POST /usage/reserve` body `{library_id, kind, operation_ids:[uuid,...]}` -> `{operations:[UsageOperation], access:AccessSnapshot}`. Bounded batch (max 1000), duplicates rejected; atomically reserve all new IDs. `demo_groups` reserves quantity, the others monthly usage.
- `POST /usage/commit` body `{library_id, operation_ids:[uuid,...]}` -> same envelope, idempotent.
- `POST /usage/cancel` body same -> same envelope, idempotent; committed state never refunded.
- `POST /usage/status` body same -> same envelope without charging.
- `POST /groups/reconcile` body `{library_id, group_ids:[uuid,...], generation:<optional integer>}` -> `{generation, access}`; additive inventory, legacy registration permitted above cap. Group ID is the operation/object identity for new groups.
- `POST /groups/delete` body `{library_id, group_ids:[uuid,...]}` -> `{generation, access}`; explicit idempotent ownership-scoped deletion.
Admin: `POST /api/v1/admin/users/{user_id}/groups/reset` body `{reason}`; support-or-higher + strict targeting, durable audit and generation increment. Add staff UI action with named confirmation and reason, not a public reset.

`AccessSnapshot`: `{protocol_version:1, server_time:ISO_UTC, tier:basic|plus|pro, paid_cycle_anchor:ISO_UTC|null, subscription_expires_at:ISO_UTC|null, group_generation:int, features:[FeatureAccess], lease:string|null}`.
`FeatureAccess`: `{id, allowed:bool, min_tier, monthly_limit:int|null, limit:int|null, limit_period:calendar_month|activation_month|null, scope:account, used:int, reserved:int, remaining:int|null, resets_at:ISO_UTC|null}`. `null` limit/remaining means genuinely unlimited, never unknown data. Paid denied features are `allowed:false`; quota exhausted is distinguished from missing paid entitlement.
`UsageOperation`: `{operation_id, kind:demo_import|custom_sets|demo_groups|null, state:unknown|reserved|committed|cancelled|expired, expires_at:ISO_UTC|null}`; commit and status return durable final state. `kind` is null ONLY for unknown operations or cancellation-before-reservation tombstones. Status returns exactly one result per requested ID; unknown is read-only, with null kind/expiry. Cancel of an unknown ID writes a durable cancelled tombstone bound to account/library so a delayed reserve cannot resurrect it; cancelled IDs are never reusable. Commit of unknown IDs fails atomically with `operation_conflict`, without charges. On unknown status, desktop retries reserve using the SAME IDs if still desired, or cancels; no replacement IDs while outcome is uncertain.

Frozen feature IDs: `demo_import`, `custom_sets`, `demo_groups`, `replay2d`, `advanced_stats`, `content_search`, `voice`, `notes`, `playbooks`.

Error envelope follows existing `AppException` handler: top-level `{code,message,access?}`, with snapshot in `access`, not `detail` or `params`. Uppercase names below denote enum identifiers; wire values are lowercase (`quota_exceeded`, `quota_reservation_expired`, `operation_conflict`, `library_reconciliation_required`, `feature_requires_tier`, `access_protocol_unsupported`). Existing auth codes and `422 validation_failed` with `detail` array remain unchanged.

Use existing structured API errors plus stable codes: `QUOTA_EXCEEDED` (409, include updated snapshot), `QUOTA_RESERVATION_EXPIRED` (409), `OPERATION_CONFLICT` (409), `LIBRARY_RECONCILIATION_REQUIRED` (409), `FEATURE_REQUIRES_TIER` (403), `ACCESS_PROTOCOL_UNSUPPORTED` (409), unauthenticated 401. Desktop IPC returns recoverable structured errors, not opaque text parsing. Validation sizes and bounded retries; do not retry 401/403 as connectivity loss. No paths, names, content, demo hashes or local analysis progress cross this API. Audit/logs must not include tokens/lease/private key.

## 8. Signed offline entitlement

Online snapshot authorizes paid operations only while session is valid. Server signs a lease valid <=24h and <=subscription expiry. Signature is asymmetric Ed25519, private key server-only, dedicated to entitlement signing, with key ID and issuer/audience/protocol. Desktop pins trusted public key(s) in build configuration; NEVER learns trusted keys from unauthenticated payload or embeds server/shared signing secret. Claims bind account and session, tier, issue/expiry, paid-cycle anchor/protocol. Validate signature and all bindings; reject future issue time, invalid algorithm, unknown key, expired lease for paid features. Missing key config disables lease issuance (fail closed), not signature verification. Configuration/rotation documented, no production secrets generated or changed here.

Frozen lease wire contract (coordinator accepted and relayed to both implementation owners): compact JWS with three unpadded base64url segments; header `alg=EdDSA`, `typ=WD-ENTITLEMENT+jwt`, nonempty configured `kid`. Ed25519 signs the ASCII header.payload. Claims: `iss=watchdemo`, `aud=watchdemo-desktop` (single string), `sub` account UUID string, `sid` validated auth-session UUID string, `tier` basic/plus/pro, `iat` and `exp` integer Unix UTC seconds, `paid_cycle_anchor` ISO UTC string or null, `subscription_expires_at` integer Unix seconds or null, `protocol_version=1`. Reject arbitrary algorithms and token-supplied keys (`jku`, `jwk`, `x5u` are not trust sources). Server config uses private PEM/key ID, server only. Desktop compile-time `WATCHDEMO_ENTITLEMENT_PUBLIC_KEYS_JSON` maps `kid` to base64 raw 32-byte Ed25519 public key. Missing/invalid trust config never grants offline paid access. Sign Basic identity leases too; expiration permits cached identity only, not paid access. On online receipt require lease account/session consistency with profile and TLS-obtained access-token `sub`/`sid`; unverified access JWT is not an entitlement source. Persist those bindings for offline verification.

Persist signed lease and minimally necessary cached profile/current-account pointer in OS keyring, not token plaintext in SQLite or frontend storage. Cached profile identity must be bound to signed subject; logout/definitive server session rejection clears cached authorization. Network failure may use valid lease, never upgrades permission. Persist highest trusted/observed time in protected storage; process monotonic elapsed time + rollback detection prevent ordinary clock rollback renewal. Reboot does not restart 24h. A hostile OS/keyring/binary remains outside guarantee.

After paid lease expires, existing local library can still be opened with Free permissions using a previously verified account identity; no new imports/groups/sets offline. This refines the earlier startup wording: updater network failure may permit local cached-account access, with PAID capabilities only if lease is valid. Online mandatory update behavior stays; installer/signature failures and explicit update-required responses must not be treated as generic offline permission. The updater adapter must preserve typed transport errors separately from configuration, invalid metadata, HTTP policy and verification failures (its old blanket `Network` mapping is insufficient). A known mandatory-update result remains blocking after a later download failure. Revocation while offline may remain delayed up to lease expiry, never beyond24h. Definitive auth rejection clears paid grant; mere 5xx/network error is not proof of revocation.
