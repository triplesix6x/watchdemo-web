# A «Фокус»: интерактивный прототип

Основа выбрана пользователем после сравнения трёх направлений. Пользователь также выбрал локальный подъём под курсором и волну при нажатии. Это отдельный прототип первого экрана, не внедрение полного редизайна.

## Открыть

http://127.0.0.1:4402/

Из корня репозитория:

```bash
cd docs/design-focus
# node_modules — локальная ссылка на существующие frontend/node_modules
node node_modules/vite/bin/vite.js
```

Сервер слушает только 127.0.0.1. Для повторного создания ссылки после переноса:

```bash
ln -s ../../frontend/node_modules node_modules
```

Рабочий сайт и desktop не меняются. Прототип не обращается к backend, Steam или CS2. Верхняя полоса — инструменты проверки прототипа, не часть будущего продуктового интерфейса.

## Что работает

- Композиция A, исходные Onest, реальные данные на исходном изображении продукта, выразительный оранжевый второй акцент и синий CTA.
- Настоящий WebGL2 ReactBits Topography: подъём под курсором, волна при нажатии и по доступной с клавиатуры кнопке «Показать волну».
- Пассивные Pointer Events: фон не перехватывает прокрутку. Нажатия на ссылки и кнопки исключены из обработки декоративного рельефа.
- Единственный GSAP ticker, остановка рендера вне экрана/скрытой вкладки, очистка GPU-ресурсов и обработчиков при размонтировании.
- Статический fallback при отсутствии WebGL, потере контекста, reduced motion, reduced transparency и повышенном контрасте. Ручная кнопка «Статичный фон» позволяет сравнить композицию без движения.
- Увеличенная по ширине поверхность рельефа на телефоне, чтобы узкий экран не сжимал перспективу в узкую полосу.

## Ограничения

Изображение приложения остаётся цветовым исследованием исходного скриншота, а не работающим desktop. CTA намеренно ведёт к пояснению вместо скачивания. Реальное видео WatchDemo → CS2 ещё ожидается. Исходная 2D-история не перенесена: это следующий отдельный эпизод, а не выдуманная замена. Ни скорость Windows-запуска, ни native-интеграция этим прототипом не проверяются. Итоговая яркость рельефа и полный редизайн ещё требуют визуального согласования.

## Источник рельефа

`terrain/Topography.tsx` основан на https://github.com/DavidHDev/react-bits/tree/main/src/ts-default/Backgrounds/Topography . Сохранена лицензия MIT + Commons Clause в `terrain/LICENSE.md`. Для прототипа использована ранее сохранённая в локальном архиве адаптация официального компонента, не заново написанная имитация.

Изменения относительно официального источника: существующий GSAP ticker вместо отдельного RAF; лимит геометрии 60000 ячеек; ресурсная очистка и совместимость со StrictMode; отсутствие рендера напрямую из ResizeObserver; исключение интерактивных HTML-контролов из декоративных pointer-эффектов; маркер успешного рендера для статического fallback. Старый лимит 24fps убран из этого прототипа: отклик получает доступные тики единственных часов. Это не обещание или измерение 60fps.

`public/assets` и базовый `public/review.css` взяты из соседнего статического исследования. Локальные шрифты и исходные изображения скопированы, внешние CDN не используются.

## Воспроизвести проверку

При запущенном сервере из корня репозитория:

```bash
cd docs/design-focus
node node_modules/typescript/bin/tsc -p tsconfig.json
node node_modules/vite/bin/vite.js build
cd ../..
node docs/design-focus/qa.mjs
```

Playwright использует установленный `/opt/google/chrome/chrome` с включённым sandbox. QA: пять ширин 375/390/820/1280/1440; реальные GPU uniform-обновления для подъёма и волны; screenshot review; отсутствие overflow, сломанных изображений и page-errors; axe WCAG2A/AA/2.1AA; переход CTA; остановка рендера вне экрана; reduced motion; возврат живого контекста после переключения; отдельные mobile touch tap и нативная прокрутка через touch sequence; отсутствие WebGL. Отчёт и изображения — в `shots/`.

Число draw calls используется только как доказательство реальной работы и остановки рендера, не как benchmark. Эти проверки не являются полным UX-аудитом готового сайта, оценкой Awwwards или проверкой всех native-состояний.
